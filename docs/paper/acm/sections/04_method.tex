\section{AlignmentGraph-ISD}
\label{sec:method}

\subsection{Multi-agent decomposition by ISD concern}
\label{sec:decomposition}

A complete ADDIE program is a long-form, multiply constrained generation task; a
single-shot system requires the model to retain the entire evolving program within
one call. For small models, several lines of evidence indicate that this
organization is disadvantageous and that decomposition is a principled alternative:
prompt decomposition improves tasks that exceed the capacity of a single call
~\cite{zhou2023leasttomost,khot2023decomposed}; separating generation from checking
improves constraint compliance~\cite{ferraz2024decrim}; small models are weak at
tool use, but decomposed multi-agent frameworks narrow the gap with large models
~\cite{shen2024multillmagent}; agent scaffolding carries much of the quality at
0.5B--3B scale~\cite{kang2025agentdistill}; and SLMs may suffice for agentic
workloads when the architecture handles coordination~\cite{belcak2025slm}. In ISD,
decomposition also matches the domain structure: the process already separates
needs--objective--assessment--activity--implementation--evaluation concerns
~\cite{branch2009addie}. AlignmentGraph-ISD therefore uses six specialist agents
\[
\mathcal{S}=\{s_{\mathrm{needs}},\,s_{\mathrm{obj}},\,s_{\mathrm{asm}},\,
s_{\mathrm{act}},\,s_{\mathrm{impl}},\,s_{\mathrm{eval}}\},
\]
each responsible for exactly one concern in this order (\Cref{tab:specialists}).
On this basis, multi-agent decomposition is the MAS's inherited architectural
foundation; the next two subsections describe the graph-context and verifier
mechanisms built on that foundation.

Decomposition, however, creates a new problem while addressing model capacity: it
splits the program into artifacts generated by different calls, so no single call
retains consistency among them---the property at the center of constructive
alignment. The specialists therefore require shared state as their coordination
core.

\subsection{Alignment graph: Coordination core and structural alignment}
\label{sec:alignment-graph}

The form of this shared state follows from an educational-theory premise.
Constructive alignment defines the quality of an instructional design through the
relationships among learning objectives, teaching--learning activities, and
assessment, rather than through the quality of each artifact in isolation
~\cite{biggs1996enhancing,biggs2011teaching}. Quality-review practice operates on
the same relationships: Quality Matters requires measurable objectives and
requires assessments, materials, and activities to support those objectives
~\cite{qm2018rubric}. If quality resides in relationships, those relationships
should be first-class objects in generation state instead of being inferred from
prose after generation. AlignmentGraph-ISD implements this implication through a
shared alignment graph $G=(V,E)$: nodes are design artifacts and edges are typed
relationships among them; \Cref{tab:graph-spec} specifies each component. For an
objective $o$, three central relationships define structural coverage:

\begin{table}[t]
  \caption{Specification of the components of the alignment graph $G=(V,E)$.}
  \label{tab:graph-spec}
  \small
  \begin{tabular}{@{}lp{0.6\columnwidth}@{}}
    \toprule
    Symbol & Specification \\
    \midrule
    $v\in V$ & Node: a design artifact with type $\tau(v)\in\mathcal{T}$;
    $\mathcal{T}$ contains needs--context, objective, assessment, activity,
    material, implementation, and evaluation---one per specialist concern. \\
    $\mathcal{R}$ & Set of 13 relationship types among artifacts; the three
    central alignment types are \emph{measures}, \emph{supports}, and
    \emph{evaluates}. \\
    $(v_s,v_d,r)\in E$ & Edge: source node $v_s$ relates to destination node $v_d$
    through relation type $r\in\mathcal{R}$. Each edge carries evidence, a
    rationale, and the mechanism by which it was established. \\
    $E_r$ & Source--destination pairs connected by relation type $r$:
    $E_r=\{(v_s,v_d)\colon (v_s,v_d,r)\in E\}$; used in \Cref{eq:aligned}. \\
    \bottomrule
  \end{tabular}
\end{table}
\begin{equation}
\label{eq:aligned}
\mathrm{aligned}(o) \iff
\bigwedge_{r\in\mathcal{R}_0}\;\exists\, v\in V\colon (v,o)\in E_r,
\end{equation}
where $\mathcal{R}_0=\{\text{measures},\text{supports},\text{evaluates}\}$ contains
the three central relation types in \Cref{tab:graph-spec}: objective $o$ has
structural coverage when there is a node that measures it (an assessment item), a
node that supports it (a learning activity), and a node that evaluates it (an
evaluation item)---the same three facets required in Quality Matters review.

The graph coordinates specialists through the tool set that the MAS provides
to each one. Every $s\in\mathcal{S}$ operates as a triple
\begin{gather*}
s=\langle C(s),\; g_s,\; W(s)\rangle,\\
C(s)\subseteq G,\qquad
W(s)=(\mathcal{T}_s,\mathcal{R}_s),\quad
\mathcal{T}_s\subseteq\mathcal{T},\;
\mathcal{R}_s\subseteq\mathcal{R},
\end{gather*}
comprising three operations for reading the graph, generating content, and writing
to the graph:
\begin{itemize}
  \item \emph{Read}---context slice $C(s)$: before generation, the MAS gives
  $s$ a one-hop graph slice filtered to the relationships needed by $s$'s concern,
  together with the design brief and stable ISD guidance. Upstream premises thus
  enter the call in structured form, and the model need not reconstruct the program
  from prose.
  \item \emph{Generate}---$g_s$: the model generates content for $s$'s concern
  from the prepared context; each generated item must declare the identifier of
  the upstream objective it serves.
  \item \emph{Write}---contract $W(s)$: $s$ may write only nodes with types in
  $\mathcal{T}_s$ and edges with types in $\mathcal{R}_s$; the MAS resolves
  declared identifiers by direct lookup (without traversal) and writes typed edges.
  Required links originate in this write step, and later specialists cannot
  silently modify upstream premises.
\end{itemize}

\subsection{Pedagogical verifier and repair loop}
\label{sec:qc}

The graph deterministically guarantees the structural layer: every relationship is
explicit, \Cref{eq:aligned} is machine-checkable, and any missing facet for an
objective is visible. The content within those nodes and edges, however, is the
product of generation call $g_s$ and may fail for a small model: content can be
missing, malformed, or inconsistent with its own instructions. For example, the
existence of a \emph{measures} edge does not mean that the assessment actually
measures the objective's content and cognitive level. Prior work shows that
post-generation checking can improve compliance
~\cite{ferraz2024decrim,madaan2023selfrefine}; the MAS therefore places a
backstop after each generation call: a pedagogical verifier checks automatically
testable \emph{necessary conditions} for pedagogical appropriateness and triggers
repair when they are violated.

After each graph update, the verifier applies to the newly written artifacts the
subset of content-level checks that the specialist which produced them owns
(\Cref{tab:verifier-checks}). Ownership follows the write contract $W(s)$: a
specialist is asked to repair only what it is permitted to write, so no check is
raised against an agent that cannot act on it. Under this rule
$s_{\mathrm{needs}}$ owns no checks---the needs--context profile carries no
alignment relationship and no cognitive-level claim---so it is the one specialist
without a verify-and-repair stage.

\begin{table}[t]
  \caption{Content-level checks performed by the pedagogical verifier: each
  check's procedure and targeted failure class.}
  \label{tab:verifier-checks}
  \small
  \begin{tabular}{@{}p{0.17\columnwidth}p{0.37\columnwidth}p{0.3\columnwidth}@{}}
    \toprule
    Check & Procedure & Purpose \\
    \midrule
    Relations and coverage & deterministic graph lookup: a declared identifier
    must resolve to an edge; count the three facets of \Cref{eq:aligned} for each
    objective & detect declared objectives that no artifact measures, supports, or
    evaluates \\
    Bloom verb--level & compare the objective's action verb with the
    Anderson--Krathwohl verb set for its declared level
    ~\cite{anderson2001taxonomy} & detect ambiguous objectives or cognitive-level
    mismatches that prevent the assessment from measuring the intended demand \\
    Assessment & check the presence and consistency of format and scoring criteria
    for each item & detect unscorable assessments---questions without criteria \\
    Active practice & check that every objective has a corresponding active
    practice activity & detect designs in which learners do not practice the
    behavior required by the objective \\
    Implementation feasibility & compare the implementation plan with contextual
    constraints in the brief & detect plans that cannot be implemented under the
    stated conditions \\
    \bottomrule
  \end{tabular}
\end{table}

When a check detects a violation, the MAS does not regenerate the entire phase.
It packages the violation with the relevant nodes and edges and returns it to the
specialist that owns the artifact under $W(s)$; that specialist issues a targeted
generation call $\mathrm{repair}_s$ over the violated artifacts alone, and the
resulting patch is written back under the same contract $W(s)$. A fixed budget $K$
bounds repair iterations; deterministic fallbacks handle malformed responses; and violations
that cannot be repaired locally and safely remain visible as warnings.

This process leaves an audit trail: executed checks, detected violations,
corresponding repair attempts, and residual warnings are stored in graph state and
exported with the final graph dump (\Cref{sec:orchestration}). The verifier thus
serves both as a check-and-repair backstop during execution and as a source of audit
evidence for educators.

\subsection{End-to-end workflow and orchestration}
\label{sec:orchestration}

\Cref{alg:harness} summarizes execution on a fixed LangGraph
\texttt{StateGraph}, and \Cref{fig:architecture} draws the same control flow. The
specialists are chained in one fixed order, so a specialist sees every upstream
artifact through $C(s)$ and cannot alter it: the sequence, not a routing decision,
determines what is available when. The verify-and-repair loop is local to the
specialist that has just written, and only the two post-loop steps
$\mathrm{aggregate}(G)$ and $\mathrm{audit}(G)$ read the whole graph. Roles remain
distinct throughout: the model proposes content only through the generation calls
$g_s$ and $\mathrm{repair}_s$; the MAS controls decomposition, state
transitions, checking, and assembly. The MAS assumes that the design brief has
been supplied and that the backbone is stateless across calls; graph $G$ retains
cross-call state.

\begin{algorithm}[t]
  \caption{AlignmentGraph-ISD execution workflow}
  \label{alg:harness}
  \KwIn{design brief $b$; repair budget $K$}
  \KwOut{ADDIE program; graph dump (JSON + DOT)}
  $G \leftarrow \emptyset$\;
  \For{$s \in (s_{\mathrm{needs}}, s_{\mathrm{obj}}, s_{\mathrm{asm}},
       s_{\mathrm{act}}, s_{\mathrm{impl}}, s_{\mathrm{eval}})$}{
    $ctx \leftarrow C(s)$\;
    $draft \leftarrow g_s(b,\, ctx)$\;
    $G \leftarrow \mathrm{write}(G,\, draft,\, W(s))$\;
    $k \leftarrow 0$\;
    $V \leftarrow \mathrm{verify}(G,\, s)$ \tcp*{owned checks; $\emptyset$ for $s_{\mathrm{needs}}$}
    \While{$V \neq \emptyset$ \textbf{and} $k < K$}{
      $patch \leftarrow \mathrm{repair}_s(V)$ \tcp*{targeted patch}
      $G \leftarrow \mathrm{write}(G,\, patch,\, W(s))$\;
      $V \leftarrow \mathrm{verify}(G,\, s)$\;
      $k \leftarrow k + 1$\;
    }
  }
  $output \leftarrow \mathrm{aggregate}(G)$\;
  $G \leftarrow \mathrm{audit}(G)$ \tcp*{residual $\to$ warnings}
  \Return $(output,\ \mathrm{dump}(G))$\;
\end{algorithm}

At the end of every run, the complete $G$ is exported as JSON and DOT, separate
from the execution trajectory. An instructional designer can trace which
assessment measures which objective, inspect weakly supported relationships, and
then revise or override the design according to the teacher-in-the-loop principle.

The three components carry different levels of evidence in this study, and we
claim them accordingly: decomposition is the inherited architectural foundation
associated with output robustness at the system level; graph context is the
mechanism whose effect on the alignment scores the ablation tests directly;
and the verifier is a check-and-repair backstop and a source of audit evidence,
not a component claimed to raise scores (\Cref{sec:conditions,sec:ablation}).
